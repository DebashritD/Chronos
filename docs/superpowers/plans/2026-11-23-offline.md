# Offline Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chronos opens with no connection, shows the last-seen data, lets habits be marked offline and syncs the
marks automatically when the connection returns.

**Architecture:** `vite-plugin-pwa` (Workbox) precaches the app shell; TanStack Query's persister saves the query
cache and paused check-in mutations to IndexedDB (`idb-keyval`). Check-in save/clear become keyed, serially scoped
mutations whose defaults (`setMutationDefaults(['checkIn'], …)`) let restored mutations resume; an optimistic patch
updates cached weeks at once, and a pure `localTodayWeek` derives today's periods on the device after midnight. The
session falls back to a saved `me` on network errors and never drops queued marks on a 401.

**Tech Stack:** React 19, TypeScript 7, Vite 8, Tailwind v4, TanStack Query v5 (+ `@tanstack/react-query-persist-client`,
`@tanstack/query-async-storage-persister`), `idb-keyval`, `vite-plugin-pwa` 2 (peer `vite ^8.0.0` supported), Vitest +
Testing Library + jsdom, Playwright.

Spec: `docs/superpowers/specs/2026-11-23-offline-design.md`. All commands run from `web/`.

## Global Constraints

- Scope: read + mark. Check-in save/clear works offline. Creating, editing, pausing and archiving habits needs a connection.
- No backend changes. No API change. Conflicts: replay wins — a queued mark is sent as-is and overwrites the server value.
- Service worker: `registerType: 'autoUpdate'`, `navigateFallback: 'index.html'`, `navigateFallbackDenylist: [/^\/api\//]`,
  `manifest: false` (reuse `public/manifest.webmanifest`); it caches no `/api` responses. A new version activates
  silently and applies on the next launch.
- Persister: `idb-keyval`, key `chronos-cache`; `maxAge` 7 days; `buster` is `CACHE_VERSION`, starting at `'1'`,
  bumped by hand only when the shape of cached data changes. Query `gcTime` is 7 days. Queries keep `networkMode: 'online'`.
- Saved session: `localStorage` key `chronos.me`.
- Mutation key `['checkIn']`; variables `{ op: 'save' | 'clear', habitId, periodStart, color?, note? }`.
- After the queue drains, `['stats']` is invalidated once.
- Copy, exactly:
  - "{n} marks haven’t synced. Log out anyway?" / "1 mark hasn’t synced. Log out anyway?"
  - "Couldn’t sync {habit name}. Refreshed." (toast, auto-dismisses after 4 s)
  - "Offline" / "Offline · {n} waiting to sync" (1: "Offline · 1 waiting to sync") / "Syncing {n}…"
  - "Connect to load this week." / "Connect to load this month."
- `SyncStatus` is a dim `text-[13px]` line under the page date on Today and Progress, hidden when online and nothing is pending.
- `WakingNotice` is hidden while offline.
- Copy uses curly apostrophes (’); no exclamation marks. Red never colours text.
- macOS is case-insensitive: never create two files in one directory differing only by case.

## Spec adjustments (code facts the spec didn’t match)

1. `Me` (`MeResponse`) has no user id — `{ username, timezone, maxYellows }`. "Same user id" is checked by `username`.
2. TanStack runs unscoped mutations in parallel. To replay "in order" the check-in defaults set `scope: { id: 'checkIn' }`.
3. A 401 can’t leave a TanStack mutation *paused* (only `onlineManager` pauses). Instead the check-in `mutationFn`
   waits on an auth gate after a 401 and resends once the same user logs back in; the different-user path rejects the
   wait. Pending check-ins are dehydrated whether paused or waiting, and all of them are resumed after restore.
4. TanStack v5’s `onlineManager` starts as online regardless of `navigator.onLine`; the app seeds it with
   `onlineManager.setOnline(navigator.onLine)` at startup so a cold offline launch pauses instead of retrying.
5. New day offline: when the derived period start equals the saved `current.periodStart`, the saved `state`, `note`
   and `editable` are kept and `closesAt` is computed locally (same value the server would send). The optimistic patch
   also advances `current` when a mark targets a newer period than the cached `current`, so marking a derived
   fresh period sticks.
6. `localTodayWeek` derives only when the device’s today is *after* `week.today` (not merely different), so a device
   clock slightly behind the server never moves Today backwards.
7. The save/clear hooks resolve as soon as a mark is queued, so cards and the picker never wait on the network;
   rejected marks surface only as the sync toast (the inline card/picker error for check-ins goes away).
8. Progress has no date line; its `SyncStatus` sits directly under the header row.

/** Calendar dates and midnights in an IANA timezone, using Intl only (no timezone library). */
const formatters = new Map<string, Intl.DateTimeFormat>()

function formatter(timeZone: string): Intl.DateTimeFormat {
  let f = formatters.get(timeZone)
  if (!f) {
    f = new Intl.DateTimeFormat('en-US', {
      timeZone, hourCycle: 'h23', year: 'numeric', month: '2-digit', day: '2-digit',
      hour: '2-digit', minute: '2-digit', second: '2-digit',
    })
    formatters.set(timeZone, f)
  }
  return f
}

/** The wall-clock date in `timeZone` at instant `at`, and that wall-clock time read as if it were UTC. */
function wallClock(timeZone: string, at: number): { date: string; asUtc: number } {
  const parts = Object.fromEntries(formatter(timeZone).formatToParts(new Date(at)).map((p) => [p.type, p.value]))
  const date = `${parts.year}-${parts.month}-${parts.day}`
  return { date, asUtc: Date.parse(`${date}T${parts.hour}:${parts.minute}:${parts.second}Z`) }
}

/** "YYYY-MM-DD" in `timeZone` at `now`. */
export function todayIn(timeZone: string, now: Date): string {
  return wallClock(timeZone, now.getTime()).date
}

/** Midnight at the start of `date` in `timeZone`, as the server formats instants ("2026-11-18T18:30:00Z"). */
export function startOfDayIn(date: string, timeZone: string): string {
  const midnightAsUtc = Date.parse(`${date}T00:00:00Z`)
  const offset = (at: number) => wallClock(timeZone, at).asUtc - Math.floor(at / 1000) * 1000
  // Second pass corrects for an offset change (DST) between the guess and the answer.
  const guess = midnightAsUtc - offset(midnightAsUtc)
  return new Date(midnightAsUtc - offset(guess)).toISOString().replace('.000Z', 'Z')
}
```

import type { CurrentPeriod, Habit, WeekHabit, WeekView } from '../../api/types'
import { addDays, weekdayIndex } from '../../lib/dates'
import { startOfDayIn, todayIn } from '../../lib/zonedTime'

type Schedule = Pick<Habit, 'frequency' | 'intervalDays' | 'startDate'>

function periodLength({ frequency, intervalDays }: Schedule): number {
  if (frequency === 'WEEKLY') return 7
  if (frequency === 'EVERY_N_DAYS') return intervalDays ?? 1
  return 1
}

function daysBetween(from: string, to: string): number {
  return Math.round((Date.parse(`${to}T00:00:00Z`) - Date.parse(`${from}T00:00:00Z`)) / 86_400_000)
}

/** Mirrors the server's `HabitSchedule.periodContaining`: the period start containing `date`, or null before the first period. */
export function periodContaining(schedule: Schedule, date: string): string | null {
  const first = schedule.frequency === 'WEEKLY'
    ? addDays(schedule.startDate, -weekdayIndex(schedule.startDate))
    : schedule.startDate
  if (date < first) return null
  return addDays(date, -(daysBetween(first, date) % periodLength(schedule)))
}

/**
 * The saved week with each active habit's current period re-derived for the device's today, so Today moves on to new
 * periods offline after midnight. Same day (or habits not loaded): the saved week as is.
 */
export function localTodayWeek(week: WeekView, habits: Habit[] | undefined, timezone: string, now: Date): WeekView {
  const today = todayIn(timezone, now)
  if (today <= week.today || !habits) return week
  const saved = new Map(week.habits.map((h) => [h.id, h]))
  const rows = habits
    .filter((habit) => habit.status === 'ACTIVE')
    .map((habit): WeekHabit => {
      const row = saved.get(habit.id)
      const start = periodContaining(habit, today)
      let current: CurrentPeriod | null = null
      if (start !== null) {
        const closesAt = startOfDayIn(addDays(start, periodLength(habit)), timezone)
        const kept = row?.current?.periodStart === start ? row.current : null
        current = kept
          ? { ...kept, closesAt }
          : { periodStart: start, state: 'PENDING', editable: true, note: null, closesAt }
      }
      return { id: habit.id, name: habit.name, minText: habit.minText, targetText: habit.targetText,
        frequency: habit.frequency, intervalDays: habit.intervalDays ?? null, status: habit.status, current,
        cells: row?.cells ?? [] }
    })
  return { ...week, today, habits: rows }
}

import { createAsyncStoragePersister } from '@tanstack/query-async-storage-persister'
import type { PersistQueryClientOptions, Persister } from '@tanstack/react-query-persist-client'
import { del, get, set } from 'idb-keyval'

/** Bump by hand only when the shape of cached data changes; ordinary deploys keep saved data and queued marks. */
export const CACHE_VERSION = '1'
export const CACHE_KEY = 'chronos-cache'
export const PERSIST_MAX_AGE = 7 * 24 * 60 * 60 * 1000

export interface KeyValueStorage {
  getItem(key: string): Promise<string | null | undefined>
  setItem(key: string, value: string): Promise<void>
  removeItem(key: string): Promise<void>
}

export const idbStorage: KeyValueStorage = {
  getItem: (key) => get<string>(key),
  setItem: (key, value) => set(key, value),
  removeItem: (key) => del(key),
}

export function createPersister(storage: KeyValueStorage = idbStorage, throttleTime = 1000): Persister {
  return createAsyncStoragePersister({ storage, key: CACHE_KEY, throttleTime })
}

export function persistOptions(persister: Persister): Omit<PersistQueryClientOptions, 'queryClient'> {
  return { persister, maxAge: PERSIST_MAX_AGE, buster: CACHE_VERSION }
}

/** Forgets the saved cache (logout). Never throws: there may be no IndexedDB (tests, private modes). */
export async function clearPersistedCache(): Promise<void> {
  try {
    await del(CACHE_KEY)
  } catch {
    // Nothing saved to clear.
  }
}

import type { CellState, Color, CurrentPeriod, WeekView } from '../../api/types'

/** Variables of a queued check-in mutation (persisted with the cache, so keep them plain data). */
export interface CheckInVars {
  op: 'save' | 'clear'
  habitId: number
  periodStart: string
  color?: Color
  note?: string | null
}

/** The week as it will look once the mark syncs: shown at once, even offline. */
export function patchWeek(week: WeekView, vars: CheckInVars): WeekView {
  const state: CellState = vars.op === 'save' && vars.color ? vars.color : 'PENDING'
  const note = vars.op === 'save' ? (vars.note ?? null) : null
  return {
    ...week,
    habits: week.habits.map((habit) => {
      if (habit.id !== vars.habitId) return habit
      const current: CurrentPeriod | null = habit.current
      let nextCurrent = current
      if (current?.periodStart === vars.periodStart) {
        nextCurrent = { ...current, state, note }
      } else if (current === null || vars.periodStart > current.periodStart) {
        // A period derived on the device after midnight; localTodayWeek recomputes its closesAt.
        nextCurrent = { periodStart: vars.periodStart, state, editable: true, note, closesAt: current?.closesAt ?? '' }
      }
      return {
        ...habit,
        current: nextCurrent,
        cells: habit.cells.map((cell) => (cell.periodStart === vars.periodStart ? { ...cell, state, note } : cell)),
      }
    }),
  }
}

/** Sync failures raised outside React (mutation defaults) reach the toast through this bus. */
const subscribers = new Set<(message: string) => void>()

export function showSyncToast(message: string): void {
  for (const cb of subscribers) cb(message)
}

export function subscribeSyncToast(cb: (message: string) => void): () => void {
  subscribers.add(cb)
  return () => {
    subscribers.delete(cb)
  }
}

Behaviour of the `['checkIn']` defaults:
- `mutationFn` sends PUT `/api/habits/{id}/check-ins/{periodStart}` `{ color, note }` or DELETE; on a 401 it waits on
  the auth gate and resends (the mutation stays pending, the queue keeps its order).
- `scope: { id: 'checkIn' }` → mutations run one at a time, in order.
- `retry`: network errors / 5xx retry forever with TanStack’s backoff (paused while offline); 4xx and
  `AuthDiscardedError` don’t retry.
- `onMutate`: cancels in-flight week fetches and patches every cached `['stats','week',*]` with `patchWeek`.
- `onSuccess`: invalidates `['stats']` only when this is the last pending check-in (it still counts while its callbacks run).
- `onError` 4xx: toast "Couldn’t sync {habit name}. Refreshed." and invalidate `['stats']`. Name comes from cached
  `['habits',*]` or `['stats','week',*]` data.

/** Check-ins that hit a 401 wait here until the same user signs back in (or the queue is discarded). */
export class AuthDiscardedError extends Error {
  constructor() {
    super('Signed in as someone else; queued marks were discarded')
    this.name = 'AuthDiscardedError'
  }
}

let gate: { promise: Promise<void>; resolve: () => void; reject: (error: Error) => void } | null = null

export function waitForAuth(): Promise<void> {
  if (!gate) {
    let resolve!: () => void
    let reject!: (error: Error) => void
    const promise = new Promise<void>((res, rej) => {
      resolve = res
      reject = rej
    })
    gate = { promise, resolve, reject }
  }
  return gate.promise
}

export function authRestored(): void {
  gate?.resolve()
  gate = null
}

export function authDiscarded(): void {
  gate?.reject(new AuthDiscardedError())
  gate = null
}
```

```ts
import type { QueryClient } from '@tanstack/react-query'
import { api } from '../../api/client'
import { ApiError } from '../../api/errors'
import type { Habit, WeekView } from '../../api/types'
import { showSyncToast } from '../../lib/syncToast'
import { AuthDiscardedError, waitForAuth } from './authGate'
import { patchWeek, type CheckInVars } from './patchWeek'

export const CHECK_IN_KEY = ['checkIn'] as const

async function send(vars: CheckInVars): Promise<void> {
  const path = `/api/habits/${vars.habitId}/check-ins/${vars.periodStart}`
  for (;;) {
    try {
      if (vars.op === 'save') await api.put(path, { color: vars.color, note: vars.note ?? null })
      else await api.del(path)
      return
    } catch (error) {
      if (!(error instanceof ApiError && error.status === 401)) throw error
      await waitForAuth()
    }
  }
}

function habitName(queryClient: QueryClient, habitId: number): string {
  const listed = queryClient.getQueriesData<Habit[]>({ queryKey: ['habits'] }).flatMap(([, data]) => data ?? [])
  const inWeeks = queryClient.getQueriesData<WeekView>({ queryKey: ['stats', 'week'] }).flatMap(([, data]) => data?.habits ?? [])
  return [...listed, ...inWeeks].find((h) => h.id === habitId)?.name ?? 'a habit'
}

/** Pending = queued offline, waiting for sign-in, or in flight. */
export function pendingCheckIns(queryClient: QueryClient): number {
  return queryClient.isMutating({ mutationKey: CHECK_IN_KEY })
}

/** Refresh stats once, after the last queued mark (the settling one still counts as pending here). */
function invalidateWhenDrained(queryClient: QueryClient): Promise<void> | undefined {
  if (pendingCheckIns(queryClient) > 1) return undefined
  return queryClient.invalidateQueries({ queryKey: ['stats'] })
}

/** Defaults live on the client (not the hooks) so marks restored after a reload can resume. */
export function registerCheckInDefaults(queryClient: QueryClient): void {
  queryClient.setMutationDefaults(CHECK_IN_KEY, {
    mutationFn: (vars: CheckInVars) => send(vars),
    scope: { id: 'checkIn' },
    retry: (_failureCount, error) =>
      !(error instanceof AuthDiscardedError) && !(error instanceof ApiError && error.status < 500),
    onMutate: async (vars: CheckInVars) => {
      await queryClient.cancelQueries({ queryKey: ['stats', 'week'] })
      queryClient.setQueriesData<WeekView>({ queryKey: ['stats', 'week'] }, (week) => week && patchWeek(week, vars))
    },
    onSuccess: () => invalidateWhenDrained(queryClient),
    onError: (error, vars: CheckInVars) => {
      if (error instanceof ApiError && error.status < 500) {
        showSyncToast(`Couldn’t sync ${habitName(queryClient, vars.habitId)}. Refreshed.`)
        return queryClient.invalidateQueries({ queryKey: ['stats'] })
      }
      return invalidateWhenDrained(queryClient)
    },
  })
}
```

import { QueryCache, QueryClient, type QueryObserverOptions } from '@tanstack/react-query'
import { registerCheckInDefaults } from '../features/checkin/queue'
import { ApiError } from './errors'
import { PERSIST_MAX_AGE } from './persist'
import { notifyQueryError } from './queryErrorBridge'

/**
 * Builds the app's QueryClient, wired so every query error is reported to
 * the query-error bridge (the SessionProvider uses this to drop to visitor
 * mode on a 401), with the check-in queue's mutation defaults registered.
 * `queryDefaults` lets callers (tests) override defaults such as `retry`
 * without losing the shared wiring.
 */
export function createQueryClient(
  queryDefaults?: Partial<QueryObserverOptions>,
): QueryClient {
  const queryClient = new QueryClient({
    queryCache: new QueryCache({
      onError: (error) => notifyQueryError(error),
    }),
    defaultOptions: {
      queries: {
        staleTime: 30_000,
        // Persisted data must outlive unmounted pages, or it is dropped before it is saved.
        gcTime: PERSIST_MAX_AGE,
        // Don't retry 4xx ApiErrors (e.g. 401/404) - they won't succeed on
        // retry and a 401 should reach the bridge immediately.
        retry: (failureCount, error) =>
          failureCount < 1 && !(error instanceof ApiError && error.status < 500),
        ...queryDefaults,
      },
    },
  })
  registerCheckInDefaults(queryClient)
  return queryClient
}

interface CheckInKey {
  habitId: number
  periodStart: string

// The streak before each save, for the yellow-limit check once it syncs (keyed by the queued variables object).
const streakBefore = new WeakMap<CheckInVars, Streak | undefined>()

/**
 * Marks are queued (`['checkIn']` defaults in features/checkin/queue.ts): `mutateAsync` resolves once the mark is
 * queued and shown; sync failures surface as the sync toast. When a queued yellow syncs during this session, a yellow
 * that brings the habit's run up to its limit raises the yellow-limit dialog (not when only the note changed); one
 * past the limit, which restarts the streak, gets a quieter notice. Marks restored after a reload sync without it.
 */
export function useSaveCheckIn() {
  const queryClient = useQueryClient()
  const notifyYellowLimit = useNotifyYellowLimit()
  const mutation = useMutation<void, Error, CheckInVars>({
    mutationKey: CHECK_IN_KEY,
    // Replaces the default onSuccess, so it must still run the drain-aware refresh first.
    onSuccess: async (_data, vars) => {
      await checkInSynced(queryClient)
      if (vars.color !== 'YELLOW') return
      // A failed streaks lookup only skips the dialog; the save itself succeeded.
      const streaks = await queryClient.ensureQueryData(streaksQuery).catch(() => undefined)
      const streak = streaks?.find((s) => s.habitId === vars.habitId)
      const before = streakBefore.get(vars)
      if (atYellowLimit(before) && streak && streak.current < before.current) {
        notifyYellowLimit({ kind: 'reset', name: streak.name, limit: before.yellowLimit })
      } else if (atYellowLimit(streak) && streak.yellowRun !== before?.yellowRun) {
        notifyYellowLimit({ kind: 'limit', name: streak.name, limit: streak.yellowLimit })
      }
    },
  })
  return {
    isPending: false as const,
    mutateAsync: async ({ habitId, periodStart, color, note }: CheckInKey & { color: Color; note: string | null }) => {
      const vars: CheckInVars = { op: 'save', habitId, periodStart, color, note }
      streakBefore.set(vars, queryClient.getQueryData<Streak[]>(streaksQuery.queryKey)?.find((s) => s.habitId === habitId))
      mutation.mutate(vars)
    },
  }
}

export function useClearCheckIn() {
  const mutation = useMutation<void, Error, CheckInVars>({ mutationKey: CHECK_IN_KEY })
  return {
    isPending: false as const,
    mutateAsync: async ({ habitId, periodStart }: CheckInKey) => {
      mutation.mutate({ op: 'clear', habitId, periodStart })
    },
  }
}

const KEY = 'chronos.me'

/** The last signed-in user, so the app opens offline and can tell whether a returning user owns the queued marks. */

import { expect, test, type Page } from '@playwright/test'

/** The persisted query cache as saved by idb-keyval (default database `keyval-store`, store `keyval`). */
function savedCache(page: Page): Promise<string> {
  return page.evaluate(() => new Promise<string>((resolve) => {
    const open = indexedDB.open('keyval-store')
    open.onsuccess = () => {
      const request = open.result.transaction('keyval').objectStore('keyval').get('chronos-cache')
      request.onsuccess = () => resolve(String(request.result ?? ''))
      request.onerror = () => resolve('')
    }
    open.onerror = () => resolve('')
  }))
}

test('marks a habit offline, survives a reload and syncs when back online', async ({ page, context }) => {
  const username = `e2e_off_${Date.now()}`

  await page.goto('/signup')
  await page.getByLabel('Username').fill(username)
  await page.getByLabel('Password').fill('password123')
  await page.getByRole('button', { name: 'Sign up' }).click()
  await page.getByRole('link', { name: 'Create your first habit' }).click()
  await page.getByRole('button', { name: 'New habit' }).click()
  await page.getByLabel('Name').fill('Read')
  await page.getByLabel('Bare minimum (YELLOW)').fill('1 page')
  await page.getByLabel('Target (GREEN)').fill('20 pages')
  await page.getByRole('button', { name: 'Create habit' }).click()
  await expect(page.getByRole('listitem', { name: 'Read' })).toBeVisible()

  await page.getByRole('navigation', { name: 'Tabs' }).getByRole('link', { name: 'Today' }).click()
  const card = page.getByRole('article', { name: 'Read' })
  await expect(card).toBeVisible()
  // The worker must control the page before going offline, or the reload has nothing to serve.
  await page.waitForFunction(() => navigator.serviceWorker.controller !== null)
  await expect.poll(() => savedCache(page)).toContain('"stats","week"')

  await context.setOffline(true)
  await expect(page.getByText('Offline', { exact: true })).toBeVisible()
  await card.getByRole('button', { name: 'Target', exact: true }).click()
  await expect(card.getByRole('button', { name: 'Target', exact: true })).toHaveAttribute('aria-pressed', 'true')
  await expect(page.getByText('Offline · 1 waiting to sync')).toBeVisible()
  await expect.poll(() => savedCache(page)).toContain('"checkIn"')

  await page.reload()
  const reloaded = page.getByRole('article', { name: 'Read' })
  await expect(reloaded.getByRole('button', { name: 'Target', exact: true })).toHaveAttribute('aria-pressed', 'true')
  await expect(page.getByText('Offline · 1 waiting to sync')).toBeVisible()

  await context.setOffline(false)
  await expect(page.getByText(/waiting to sync|Syncing/)).toHaveCount(0)

  const response = await page.request.get('/api/stats/week')
  expect(response.ok()).toBe(true)
  const week = (await response.json()) as { habits: { name: string; current: { state: string } | null }[] }
  expect(week.habits.find((h) => h.name === 'Read')?.current?.state).toBe('GREEN')
})
